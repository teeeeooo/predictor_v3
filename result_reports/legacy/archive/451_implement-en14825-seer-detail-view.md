# 451 Implement EN14825 SEER Detail View

## Goal

Expose EN14825 SEER Declared/Tested bin diagnostics through the shared detail
surface while preserving the existing `calculate_seer()` result contract and
numerical output.

## Scope

- Add a core-owned additive detail path using the existing SEER bin loop.
- Preserve completed Declared/Tested detail payloads in the UI result model.
- Normalize raw rows through a compact SEER detail schema/formatter.
- Connect detail toggle, dynamic source selection, status clearing, copy/CSV,
  and visible-content refit notification to the SEER section.
- Add focused core, adapter, formatter, and section regression tests.

## Non-goals

- No config/schema/fixture/golden, SCOP/AHRI, batch, sample-data, point
  contribution, seasonal-summary, common panel, or result-key change.

## Task Results

- `_calculate_seer_on()` remains the sole SEER bin-loop/formula owner and can
  optionally collect temperature, hours, cooling load, EERpl, numerator,
  energy contribution, and interpolation source diagnostics.
- `calculate_seer()` still returns exactly `seer`, `seer_on`, and `qc_kwh`.
  `calculate_seer_with_details()` is an additive path that returns those same
  values plus `bin_details` generated by the same core loop.
- `SeerAdapter` prefers the detail-capable method and remains compatible with
  injected legacy/fake calculators that only implement `calculate_seer()`.
- The section presents only completed Declared/Tested sources. Invalid input or
  calculation failure clears stale rows and shows a user-facing status.
- The established `BinDetailPanel` owns graph, read-only table, copy, and CSV;
  no UI-side calculation or new export implementation was introduced.

## Numerical Evidence

- The focused core regression asserts the legacy result key tuple is unchanged.
- Every legacy result value equals the matching detail-path value.
- The sum of per-bin numerator contributions divided by the sum of per-bin
  energy contributions matches the existing rounded `seer_on` result.
