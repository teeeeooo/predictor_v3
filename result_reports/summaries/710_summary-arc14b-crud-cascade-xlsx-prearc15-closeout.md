## Major Decisions

- Data Mapping Manager is no longer only a read-only foundation surface. It now
  supports user-facing draft projection, validation, editable row CRUD,
  validation-gated save, dirty reload confirmation, JSON export, and generated
  XLSX read-only snapshot export.
- `mapping.json` remains the runtime SSOT. Data Mapping writes owned runtime
  sections with backup/temp/atomic replace and preserves unowned sections.
- Predict dropdown fallbacks for `ref_type` and `exp_type` are removed.
  Missing/empty mapping sections become empty/status-visible states instead of
  hard-coded options.
- Runtime Cascade is integrated: Predict dropdown/autofill behavior consumes
  `odu_cascade`, `cond_specs`, `fin_type`, `pi`, and `row` generated by Data
  Mapping Manager.
- Import and export-edit-reimport remain excluded. JSON/XLSX exports are
  read-only review/share/report snapshots.
- Generated XLSX write/export uses `openpyxl`; existing user Excel reads remain
  an `xlwings`/Excel automation workflow when needed.
- Requirements are app-scoped: Train/Predict share `requirements/ml_runtime.txt`,
  Predict excludes training-only `optuna`, and Train includes Excel dependencies.
- Before Arc 15 direction is finalized, the project must audit the relationship
  between `config/ml/features.csv`, `config/predict/schema.csv`, the legacy wide
  mapping fixture, Data Mapping Manager outputs, and real training data outside
  the repo.

## Runtime And UI Behavior

- Data Mapping editable groups are IDU, Evap Index, ODU, Compressor,
  Refrigerant, Expansion, and ODU Cond Specs.
- ODU Cond Specs generates the internal cascade/spec sections instead of
  exposing those sections as separate raw tables.
- Save validates the draft, creates a backup, writes a temp file, atomically
  replaces `mapping.json`, and clears dirty state only after success.
- Reload asks for confirmation before discarding dirty draft edits.
- Export preserves dirty draft state and does not save or modify `mapping.json`.
- Predict invalid mapping status is distinct from missing mapping status.

## Requirements And Dependency State

- `requirements/base.txt`, `train.txt`, `predict.txt`, `calculator.txt`,
  `excel.txt`, `ml_runtime.txt`, and `dev.txt` define the current dependency
  surfaces.
- `openpyxl` is approved for generated XLSX write/export.
- `xlwings` remains optional/manual in the macOS development environment and is
  intended for existing user Excel read workflows in Windows user environments.
- Requirements remain unpinned because no version pinning policy was introduced.
