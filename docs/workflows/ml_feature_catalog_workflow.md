# ML Feature Catalog Workflow

## Purpose

Arc 13 makes `config/ml/features.csv` the operating contract for ML feature,
target, and one-hot feature names.

Arc 13.5 adds the default user editing surface: use `app_train.py` and the
Train/Admin `Feature Catalog` tab for validation, Excel-safe export, whitelisted
edits, and canonical save. Direct CSV editing remains an advanced fallback for
automation or recovery work.

The central rule is:

```text
ml_name = raw training data header = internal ML feature or target name
```

There is no separate training header alias or header mapping layer. Training
data must use the catalog `ml_name` values directly.

## Edit Flow

When adding or changing an ML feature through the Train/Admin editor:

1. Open `app_train.py` and select the `Feature Catalog` tab.
2. Review catalog and project consistency validation status.
3. Use CSV export when an Excel/Numbers review copy is needed; export uses
   UTF-8-SIG and does not mutate the canonical catalog.
4. Edit only the whitelisted fields: `label`, `notes`, `active`,
   `zero_fill_policy`, `source`, `mapping_key`, and `one_hot_group`.
5. Save only after validation passes; canonical save writes
   `config/ml/features.csv` as UTF-8 without BOM and reloads the catalog.
6. Align the training CSV or Excel export header to the catalog `ml_name`.
7. Run the focused catalog and ML guard tests before training.
8. Train only after the guard tests pass.

When adding a new feature row outside the current editor scope, use a bounded
developer workflow:

1. Edit `config/ml/features.csv` directly.
2. Add or update one row with a stable `feature_id`.
3. Set `role` to one of `input`, `auto`, `result`, `derived`, `one_hot`, or
   `hidden`.
4. Fill role-specific fields:
   - `input`: `ui_key`, `label`.
   - `auto`: `ui_key`, `label`, `source`, `mapping_key`.
   - `result`: `ui_key`, `label`.
   - `one_hot`: `one_hot_group`.
   - `derived`: no formula in CSV; formulas stay in code.
   - `hidden`: no direct UI column.
5. Set `zero_fill_policy`.
6. Save the file as UTF-8 comma-delimited CSV without BOM.
7. Align the training CSV or Excel export header to the catalog `ml_name`.
8. Run the focused catalog and ML guard tests before training.
9. Train only after the guard tests pass.

## User-managed Fields

The user-managed CSV owns:

- `order`
- `feature_id`
- `ml_name`
- `role`
- `ui_key`
- `label`
- `source`
- `mapping_key`
- `one_hot_group`
- `zero_fill_policy`
- `active`
- `notes`

## Code-owned Fields

Do not add these to `features.csv`:

- width or color;
- UI delegate/editor behavior;
- table widget settings;
- RFE settings;
- `model_key`;
- target-specific exclude or allowed rules;
- derived formulas;
- model artifact schema.

Width and color are derived in code from role defaults. Dropdown-only predictor
input columns and rule-only result columns are owned by
`core/predictor_schema/ui_columns.py`, not by the ML feature catalog.

## Role Notes

- `input`: user-entered ML feature exposed through predictor schema.
- `auto`: mapping-backed ML feature exposed through predictor schema.
- `result`: model target and result UI projection.
- `one_hot`: encoded ML feature generated from a grouped categorical input.
- `derived`: code-calculated feature generated by preprocessing.
- `hidden`: active internal feature that has no direct UI column.

Predictor UI-visible ML columns are ordered by role group and catalog order:

```text
input -> auto -> result
```

Rows inside each group follow the catalog `order`.

## One-hot Features

One-hot feature lists come from catalog rows with `role=one_hot`.

Current groups:

- `refrigerant`: `R410A`, `R32`, `R290`
- `expansion_device`: `EEV`, `Capi`

The Predict adapter still maps UI input keys to those groups:

- `ref_type` -> `refrigerant`
- `exp_type` -> `expansion_device`

## Zero-fill Policy

`zero_fill_policy` allowed values:

- `disallow`
- `mode_missing_allowed`

Only these four `ml_name` values may use `mode_missing_allowed`:

- `Cooling Capa`
- `Cooling Power`
- `Heating Capa`
- `Heating Power`

All other missing ML features fail fast during inference. This prevents
mapping, autofill, schema, or data-quality problems from being hidden as `0.0`.

## Training Data Contract

Training data headers must match active catalog `ml_name` values for raw
training roles:

- `input`
- `auto`
- `one_hot`
- `result`

Derived feature headers are not required in raw training data because derived
features are calculated by preprocessing code.

If a training CSV or Excel export has headers that are not catalog `ml_name`
values, training fails before fitting. If required catalog headers are missing,
training also fails before fitting.

## CSV Editing Notes

When reviewing with Numbers or Excel:

- keep the comma delimiter;
- prefer the Train/Admin `Feature Catalog` export, which writes UTF-8-SIG for
  spreadsheet auto-detection;
- do not rename headers in the training export unless the same `ml_name` change
  is made in `features.csv`;
- do not add visual presentation fields such as width or color.

## Quick Checks

Run these focused checks after catalog edits:

```bash
python3 -B -m pytest tests -k "feature_catalog"
python3 -B -m pytest tests -k "training or train or inference or ml"
python3 -B -m pytest tests -k "predict_schema or prediction_adapter or prediction_usecase or apps_predict"
```

Do not start model training until these checks pass.
